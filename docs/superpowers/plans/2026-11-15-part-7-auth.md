# Part 7 — Admin Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The single admin can sign in at `/es/admin/login/` and reach a protected, empty admin panel at `/es/admin/`. Every `/api/admin/**` endpoint requires a valid JWT. Part 8 fills the panel.

**Architecture:**
- **Backend module `auth`:**
  - `domain`: the admin account in schema `auth` (migration V9).
  - `application`: password check, JWT issuing, and a startup initializer that keeps the account in line with the `ADMIN_*` env vars.
  - `web`: `POST /api/auth/login`, `GET /api/admin/session`, and the Spring Security configuration.
- **Security rules:**
  - Spring Security is stateless: there is no session and no cookies, so CSRF does not apply.
  - It only guards `/api/admin/**`. Every other path stays public, and the existing filters (headers → CORS → rate limit → size) still run first.
  - Tokens are HS256 JWTs created and checked with Spring Security's own Nimbus support, so no extra JWT library is needed.
- **Frontend:**
  - A lazy-loaded admin area, in Spanish only and rendered in the browser.
  - It is served by real shells (`es/admin/index.html` and `es/admin/login/index.html`) that `copy-root.mjs` writes, so it answers 200, not the 404 page.
  - The token is kept in `sessionStorage`. An interceptor adds it **only** to `/api/admin/` calls on the API origin, and a guard protects the panel.

**Tech Stack:**
- Backend: Spring Boot 4.1.2, Spring Security 7 (`spring-boot-starter-security`, `spring-boot-starter-oauth2-resource-server`), BCrypt, Flyway, Testcontainers.
- Frontend: Angular 22 (lazy routes, functional guard and interceptor, Reactive Forms, signals), Vitest, node:test.

**Spec:** `docs/superpowers/specs/2026-11-14-portafolio-design.md` (§5.3 `auth` row, §5.5, §5.7 admin panel, §6 step 7)

## Global Constraints

- All code, identifiers, comments, commits and docs are in English. The admin UI copy is Spanish-only (spec §5.7), written as plain text without `i18n` markers.
- Zero cost: no new service. Secrets live only in the Render env and the local `.env`, never in the repo.
- Never edit applied Flyway migrations (V1–V8). New schema work goes in V9. `portfolio_app` keeps data-only rights.
- Errors are problem JSON. Admin and auth responses are `Cache-Control: no-store` (already true for every non-public path in `ApiHeadersFilter`).
- **JWT:**
  - HS256, secret from `JWT_SECRET`: base64, at least 32 decoded bytes;
  - issuer `portfolio-api`, `sub` = username;
  - lifetime exactly 2 hours (spec);
  - no refresh tokens (spec non-goal).
- **Admin account:** from `ADMIN_USERNAME` (3–50 characters) and `ADMIN_PASSWORD` (at least 12 characters and at most 72 UTF-8 bytes, BCrypt's limit). Only BCrypt hashes are stored.
- Login limit: 5 attempts per client per 15 minutes (`app.auth.login.attempts`, `app.auth.login.window`), keyed with `ClientAddress`.
- CORS: allowed headers become `Content-Type, Authorization`. Methods stay `GET, POST`; part 8 adds the rest.
- A cold start can take about 2 minutes. Browser calls to the API use the shared 130 s timeout and show the "waking up" hint after 5 s.
- Branch: `feat/part-7-auth` from `main` (a917e02).

## Review Focus

1. **A password longer than 72 UTF-8 bytes** (for example multibyte characters): BCrypt rejects it with an exception, which would surface as a 500. Expected: the same 401 as a wrong password. Test `overlongPasswordIsJustInvalid` in Task 3.
2. **An expired, tampered, foreign-key-signed or `alg: none` token:** expected 401 problem JSON with `WWW-Authenticate: Bearer`, never a 500 or a 200. Tests in Task 2.
3. **The token expires while the panel is open:** the next admin call returns 401. Expected: the app drops the token and goes to `/admin/login`, which says the session expired. Tests `clearsTokenAndRedirectsOn401` and `showsExpiredNotice` in Tasks 4 and 5.
4. **Render asleep when the admin opens the login:** the login page wakes the backend as it loads. While the request is in flight it shows the waking hint, it gives up at 130 s, and it keeps the username. Test `showsWakingHintThenRetryableError` in Task 5.
5. **Misconfigured env:**
   - When `JWT_SECRET` is missing or short, the app must refuse to start with a clear message, so Render keeps the previous deploy.
   - When `ADMIN_PASSWORD` is missing or weak, the app still starts, no admin exists, and a warning is logged that contains no secret values.

   Tests in Tasks 1 and 2.
